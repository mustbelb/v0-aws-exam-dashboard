## Configuration and deployment

Store only staging credentials in gitignored `.env.staging.local` (mode 0600). `NEXT_PUBLIC_SUPABASE_ANON_KEY` also accepts the project's publishable key. `SUPABASE_SECRET_KEY` is server-only. Never copy production keys into this file. Synthetic account credentials generated by tests use gitignored `.staging-test-users.json` (mode 0600).

The staging key file has been populated and configured. For future configuration changes, run `node scripts/deployment/configure-staging-app.cjs` after updating that private file. It pins the project and branch, verifies server-side access, and installs only allowlisted branch overrides without logging their values. Automatic builds stay disabled; explicitly start a staging build after configuration verification.

Amplify omits empty-string branch environment overrides. Until configuration is ready, use explicit non-secret placeholder values to override app-level production configuration, and `AUTHENTICATED_GENERATOR_URL=disabled`. Never start a build with placeholders. The staging build validator rejects production/legacy database URLs, the production table, and an active generator endpoint.

## Checks

- `npm run test:staging`: configuration isolation guards.
- `node scripts/deployment/test-staging-session.cjs`: hosted missing/invalid/valid-session and expired-session refresh checks using a synthetic account. Returns refreshed cookies to the private test credential file.
- `npm run test:issuance`: question selection, cache/publication checks, and history pagination.
- `npm run test:selection-concurrency`: local synthetic adapters only; not hosted capacity.
- `node scripts/deployment/test-staging.cjs 1 1`: one authenticated synthetic learner; bank retrieval, answer save, and retry invariants.
- After inspecting smoke results, bounded cohort options are `10`, `50`, or `100`, with `1`–`3` rounds. Stop escalation on failures or unacceptable latency. Repeated runs accumulate legitimate synthetic history and may exhaust the small fixture bank; do not reset unrelated records to keep tests running.

Hosted tests call the pinned staging app and staging Supabase project only. They do not call the generator or send signup emails. Results omit credentials and question bodies. These short tests do not establish sustained production capacity or assess browser rendering performance.

Current provisioning and test artifacts remain local in `outputs/staging/`; they are not committed. There is no automatic deletion of paid resources or test accounts.

Fresh synthetic sign-ins are paced at 2.5-second intervals, and unexpired sessions are reused to respect Supabase token endpoint rate limits. Question/submit timings include full JSON body receipt and parsing. Early baseline reports used response-header timing and are explicitly labeled in local artifacts.
